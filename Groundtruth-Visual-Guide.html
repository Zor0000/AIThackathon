01 · The user journey

Four steps to a review draft

The output helps a manager prepare. The manager owns the review and the final wording.

1 / INPUT

Set the scope

Paste the self-review. Confirm identities, dates, repositories, and project.

→
2 / EVIDENCE

Inspect each claim

See matching records, factual conflicts, and things the sources cannot establish.

→
3 / HUMAN INPUT

Resolve and recheck

Correct a claim, supply context, or exclude it. Save the reason and recheck.

→
4 / OUTPUT

Review the draft

Read supported statements, attributed context, source references, and questions.

An unresolved factual conflict pauses drafting. Clarification returns through evidence review before drafting can begin.

03 · Inside the harness

Three focused AI roles

A harness controls inputs, permissions, state, and transitions. Code enforces the drafting gate.

AGENT 01

Claim extractor

Breaks the self-review into checkable statements. Preserves the employee’s original words.

Output: claims with IDs and source quotes.

AGENT 02

Evidence reviewer

Matches statements to records. Separates factual disagreement from missing context.

Output: assessments, references, and questions.

AGENT 03

Draft writer

Writes from eligible statements and attributed context after the gate passes.

Output: draft plus unresolved discussion items.

Read-only connectors · GitHub + Jira
Fetch records within explicit source and identity boundaries. These are code adapters.
Policy gate · saved state · output checks
Pause → save clarification → recheck → draft. The writer cannot bypass this sequence.
04 · Product boundaries

Context matters as much as evidence

Leadership ≠ PR authorship

A colleague opening the PR does not disprove someone else’s leadership. Ask about design, coordination, and rollout responsibilities.

Missing data ≠ poor performance

Unavailable records become an evidence question or source error. They never become a negative judgment about the employee.

Activity ≠ a performance score

No ratings, employee rankings, team-average ticket comparisons, or recommendations about promotion or pay.

Design informed by Microsoft Research’s SPACE framework. These boundaries are our proposed product choices.
